# AI Практика — закрытый пилот помощника логиста

## Архитектура
- Интерфейс: GitHub Pages.
- Авторизация и общая база: Supabase.
- Доступ к данным ограничен авторизованными участниками рабочего пространства через RLS.
- В репозитории нет паролей, service_role keys и рабочих таблиц.

## Настройка Supabase
1. Создайте проект в https://supabase.com/dashboard.
2. Откройте SQL Editor и выполните `schema.sql`.
3. Создайте пользователей в Authentication → Users.
4. Создайте workspace и добавьте владельца и тестировщиков в `workspace_members` с ролями `owner` или `tester`.
5. После базовой схемы выполните миграции по порядку: `migrations/001_dataset_rows.sql`, `migrations/002_resumable_uploads.sql`, `migrations/003_dataset_permissions.sql`.
6. В `config.js` укажите Project URL, publishable/anon key и workspace UUID. Никогда не используйте service_role key в браузере.

## Работа с данными
1. Откройте раздел **Данные**.
2. Загружайте исходные отчёты по одному: закупки, продажи блюд, порча, инвентаризационные расхождения. Поддерживаются CSV, XLSX и XLS; читается первый лист файла.
3. После завершения всех загрузок откройте **Аналитика**.
4. Нажмите **Сформировать анализ из этих файлов**. Приложение распознает типы отчётов по заголовкам столбцов, объединит строки в отдельный аналитический набор и не изменит исходные наборы.
5. После формирования откроется аналитика: закупки, выручка, порча, недостачи, излишки, сравнение подразделений и сигналы для проверки.
6. Повторное нажатие создаёт новый аналитический набор; предыдущие наборы можно удалить по правилам доступа.

Если у вас уже есть объединённый набор с колонками `Тип отчёта`, `Подразделение`, `Наименование`, `Показатель для анализа, ₽`, `Сумма в отчёте, ₽` и `Вид операции`, его можно открыть напрямую кнопкой **Открыть анализ**.

## Роли и удаление данных
- **Владелец** видит кнопку удаления у любого завершённого или прерванного набора в своём workspace.
- **Тестировщик** может удалять только наборы, которые загрузил сам.
- Во время загрузки удаление отключено.
- При удалении набора связанные строки в `dataset_rows` удаляются каскадно.
- Исходный Excel-файл не хранится в Supabase как файл: сохраняются разобранные табличные строки.

Если владелец проекта вошёл с ролью «Тестировщик», администратор Supabase должен изменить его роль в `workspace_members` на `owner`. Пример SQL для конкретного аккаунта (подставьте email и UUID workspace):
```sql
update public.workspace_members wm
set role = 'owner'
from auth.users u
where wm.user_id = u.id
  and lower(u.email) = lower('YOUR_EMAIL')
  and wm.workspace_id = 'WORKSPACE_UUID';
```
Не повышайте роль тестировщика, если это не доверенный владелец пространства.

## Что умеет и чего пока не умеет пилот
- Автоматически объединяет четыре вида загруженных отчётов, если в файлах есть ожидаемые заголовки столбцов.
- Показывает базовые финансовые и операционные показатели, ранжирует порчу и подсвечивает крупные расхождения.
- Хранит задачи, отзывы, наборы данных и историю действий в общей базе.
- Не подключён напрямую к iiko и не отправляет заказы поставщикам.
- Пока не рассчитывает потребность в закупке по актуальным остаткам, незаведённым УПД, срокам поставки и технологическим картам.
- Результаты аналитики — сигналы для проверки, а не автоматические решения. Периоды закупок, порчи и инвентаризации необходимо подтвердить по первичным отчётам.
- До согласования с ИТ и руководством используйте только искусственные или обезличенные данные.
